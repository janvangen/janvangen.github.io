关于

我是 janvangen，一边写技术实践，一边把工作里反复踩的坑做成能跑的小工具。 我关心两件事：文档里的步骤能不能真的跑起来，以及工具的边界在哪里说清楚。 所以我写的工具都会先在我自己的流程里用够时间，再开源；README 里会写清楚"什么情况下别用"。 没有实际跑过的结论我会直接标注"没跑过"，不用听起来很确定的说法来填充页面。

  • 工具必须零依赖或只依赖标准库，否则别人根本不会用第二次。
  • README 里先写「什么时候别用」，再写怎么用。
  • 不确定的数字一定标注来源；没跑过的结论直接写「没跑过」。
  • 每个项目都配一个自检命令，让别人三十秒内确认它还活着。
